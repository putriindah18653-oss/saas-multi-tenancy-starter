# Agent Task Plan — SaaS Multi-Tenancy Starter

Repo: `/root/saas-multi-tenancy-starter`  
Remote: `https://github.com/putriindah18653-oss/saas-multi-tenancy-starter.git`  
Source spec: `IDEA.md`

## Current repo analysis

Current repository is almost empty and contains only:

- `README.md` — minimal title only.
- `IDEA.md` — complete product/technical specification.
- `.git/` — repository already initialized and tracking `origin/main`.

There is no existing backend, frontend, Docker, migration, or documentation implementation yet. Because of that, task splitting must start from foundation and use clear file ownership to avoid agent overlap.

## Global rules for all agents

1. Read `IDEA.md` before editing.
2. Do not edit files outside your assigned ownership unless explicitly listed as dependency contract.
3. Do not rename or move files owned by another task.
4. Keep implementation simple, usable, and production-minded.
5. Security requirements are mandatory:
   - never store plaintext passwords,
   - JWT secrets must come from env,
   - tenant-scoped queries must always filter by `tenant_id`,
   - do not log password/token,
   - return safe error messages.
6. Prefer small, stable dependencies.
7. Add meaningful comments only where they explain tenant isolation/security decisions.
8. Every task must finish with verification commands and notes.
9. If a task needs an interface from another task, use the contracts defined below instead of changing another agent's files.

## Recommended stack decisions

These choices reduce ambiguity and avoid conflicting implementations:

- Backend router: `chi`
- DB driver: `pgxpool`
- Migrations: plain SQL files compatible with `golang-migrate`
- Password hashing: `bcrypt`
- JWT: `github.com/golang-jwt/jwt/v5`
- IDs: UUID generated by PostgreSQL via `gen_random_uuid()` where possible
- Frontend: Vue 3 + Vite + TypeScript + Tailwind + Pinia + Vue Router + Axios
- API base path: `/api/v1`
- Dev ports:
  - backend: `8080`
  - frontend: `5173`
  - postgres: `5432`
  - redis: `6379`

**Deliverables:**

2. JWT access and refresh token generation/validation.
3. Auth context middleware.
4. Endpoints:
   - `POST /api/v1/auth/register-owner`
   - `POST /api/v1/auth/login`
   - `POST /api/v1/auth/refresh`
   - `POST /api/v1/auth/logout`
   - `GET /api/v1/me`

**Dependency contract consumed:**

**Dependency contract exposed:**


# Suggested execution order

Parallel-safe waves:

## Wave 1

Run first because they create contracts:

1. Task 01 — Monorepo/Docker/docs shell
2. Task 02 — Backend foundation
3. Task 03 — Database migrations/seed

Potential conflict: Task 01 and Task 02 both may create `backend/` folder. This is OK only if Task 01 creates empty/skeleton directories and Task 02 owns actual backend files. If using git branches/worktrees, merge Task 01 first.

## Wave 2

Run after backend contracts from Wave 1 exist:

4. Task 04 — Auth
5. Task 05 — RBAC + tenant context

These must coordinate through the auth context contract, but file ownership prevents overlap.

## Wave 3

Run after RBAC middleware exists:

6. Task 06 — App tenant management + audit
7. Task 07 — Tenant user management
8. Task 08 — Frontend foundation

Task 08 can run in parallel because it only consumes expected API contracts.

## Wave 4

Run after frontend foundation exists:

9. Task 09 — Frontend auth/layouts
10. Task 10 — Frontend tenant CRUD pages
11. Task 11 — Frontend tenant user pages

## Wave 5

Run last:

12. Task 12 — Integration hardening and docs finalization
