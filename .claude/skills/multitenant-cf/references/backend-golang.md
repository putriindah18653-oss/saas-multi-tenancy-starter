# Backend Golang — Multi-Tenant Patterns

## Data Access: sqlc (default) + pgx (escape hatch)

This skill standardizes on **sqlc** as the primary way to access data:

- You write pure SQL in `.sql` files, and `sqlc generate` produces type-safe Go code.
- There's no ORM abstraction hiding the query — SQL stays explicit.
- Eliminates manual `rows.Scan(...)` boilerplate that's prone to "swapped columns", important when there are many tenant tables.
- sqlc uses `pgx/v5` under the hood, so there's no conflict with the stack.

**When to drop down to raw `pgx` (escape hatch):** dynamic queries — optional filters, changing `WHERE` clauses, search builders, complex pagination. sqlc requires static SQL, so for these cases write directly using `pgx`. Do not fully replace with raw `pgx`; use it only where things are genuinely dynamic.

> **CRUCIAL for RLS:** sqlc generated queries accept a `DBTX` interface satisfied by `pgx.Tx`. `set_config('app.current_tenant_id', ...)` and its query **must share one transaction**. The `store.InTenant` helper below preserves this — never set the tenant on a different connection from its query, because RLS will leak/empty.

> **Naming convention (standardized, avoid ambiguity):**
> - `tenant.WithTenant(ctx, t) context.Context` — context decorator, following the Go `context.With*` idiom. Returns a context.
> - `store.InTenant(ctx, fn func(*db.Queries) error)` — runs fn **inside** an RLS-bound tx using sqlc. The `In` verb = execution scope, not a decorator.
> - `store.InTenantRaw(ctx, fn func(pgx.Tx) error)` — same, but hands over the raw `pgx.Tx` (escape hatch for dynamic queries). The `Raw` suffix = bypass sqlc.
>
> Rule: the `With*` prefix is only for things that return `context.Context`; transaction-execution helpers use `In*`.

## Tenant Context

### `internal/tenant/context.go`
```go
package tenant

import "context"

type Tenant struct {
    ID     string
    Domain string
    Plan   string
}

type contextKey string

const tenantKey contextKey = "tenant"

func WithTenant(ctx context.Context, t *Tenant) context.Context {
    return context.WithValue(ctx, tenantKey, t)
}

func FromContext(ctx context.Context) (*Tenant, bool) {
    t, ok := ctx.Value(tenantKey).(*Tenant)
    return t, ok
}

// MustFromContext — panics if there is no tenant, for handlers that require a tenant
func MustFromContext(ctx context.Context) *Tenant {
    t, ok := FromContext(ctx)
    if !ok {
        panic("tenant not found in context")
    }
    return t
}
```

## Middleware Chain

### `internal/tenant/middleware.go`
```go
package tenant

import (
    "net/http"
    "github.com/yourapp/internal/cache"
    "github.com/yourapp/internal/httperr"
)

// ResolveTenant — read X-Tenant-ID from the CF Worker and resolve to a Tenant struct.
// X-Tenant-ID is a resolution hint only. For authenticated tenant routes, AuthMiddleware
// and TenantContextMiddleware must cross-check it against the JWT tenant_id claim before
// any tenant data query runs. Login is the boundary case: no JWT exists yet, so the
// tenant comes from trusted Worker hostname resolution plus backend tenant lookup.
func ResolveTenant(repo *Repository) func(http.Handler) http.Handler {
    return func(next http.Handler) http.Handler {
        return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
            tenantID := r.Header.Get("X-Tenant-ID")
            if tenantID == "" {
                httperr.Write(w, httperr.BadRequest("missing tenant"))
                return
            }

            t, err := repo.FindByID(r.Context(), tenantID)
            if err != nil {
                httperr.Write(w, httperr.NotFound())
                return
            }

            ctx := WithTenant(r.Context(), t)
            next.ServeHTTP(w, r.WithContext(ctx))
        })
    }
}
```

## Two Connection Pools (app + platform)

Two DB roles → two pools. The app pool is subject to RLS; the platform pool bypasses RLS. Both are a single pool for all tenants (resource-efficient on a VPS), separated only by role.

### `pkg/db/postgres.go`
```go
package db

import (
    "context"
    "github.com/jackc/pgx/v5/pgxpool"
)

type Pools struct {
    App      *pgxpool.Pool // role app_user — NOBYPASSRLS (all tenant handlers)
    Platform *pgxpool.Pool // role platform_user — BYPASSRLS (platform routes ONLY)
}

// appURL  = postgres://app_user:...@host/yourdb       (role app_user — subject to RLS)
// platURL = postgres://platform_user:...@host/yourdb  (role platform_user — BYPASSRLS)
// Same database (yourdb) in both — the ONLY difference is the role.
func NewPools(ctx context.Context, appURL, platURL string) (*Pools, error) {
    app, err := pgxpool.New(ctx, appURL)
    if err != nil {
        return nil, err
    }
    plat, err := pgxpool.New(ctx, platURL)
    if err != nil {
        app.Close()
        return nil, err
    }
    return &Pools{App: app, Platform: plat}, nil
}
```

> **pgbouncer:** if there's a pgbouncer in front of Postgres, `pool_mode` MUST be `transaction` or `session`. With `statement` mode, `set_config(..., is_local=true)` can leak to other connections/transactions → tenant isolation breaks. Ideally each DB role has its own pgbouncer pool.

## Store Helper — RLS within One Transaction

The security core: every tenant data access is wrapped in a transaction that runs `set_config('app.current_tenant_id', ...)` and then uses the sqlc `Queries` bound to that `tx`. The tenant is taken from context, **never** from a parameter or request body.

### `internal/store/store.go`
```go
package store

import (
    "context"
    "github.com/jackc/pgx/v5"
    "github.com/jackc/pgx/v5/pgxpool"
    "github.com/yourapp/internal/db"      // GENERATED sqlc package
    "github.com/yourapp/internal/tenant"
)

// Store uses the APP POOL (role app_user, subject to FORCE RLS).
// Platform code that needs cross-tenant access uses a separate pool — see "Platform Routes" below.
type Store struct {
    pool *pgxpool.Pool // app_user — NOBYPASSRLS
}

func New(pool *pgxpool.Pool) *Store { return &Store{pool: pool} }

// InTenant — open tx, set the active tenant, run fn with Queries bound to the tx.
// set_config + query share the same connection → RLS active & automatically reset at the end of the tx.
// Naming note: tenant.WithTenant decorates the context (the Go With* idiom).
// store.InTenant runs fn INSIDE an RLS-bound tx — the "In" verb marks the execution scope, not a decorator.
func (s *Store) InTenant(ctx context.Context, fn func(q *db.Queries) error) error {
    t := tenant.MustFromContext(ctx)

    tx, err := s.pool.Begin(ctx)
    if err != nil {
        return err
    }
    defer tx.Rollback(ctx)

    // SET LOCAL: scoped to this transaction only, automatically reset on commit/rollback.
    if _, err := tx.Exec(ctx, `SELECT set_config('app.current_tenant_id', $1, true)`, t.ID); err != nil {
        return err
    }

    if err := fn(db.New(tx)); err != nil { // db.New(tx) → Queries bound to the tx
        return err
    }
    return tx.Commit(ctx)
}
```

> Note: use `set_config(name, value, true)` (parameterized) instead of `SET LOCAL app.current_tenant_id = $1` — `SET LOCAL` does not accept the `$1` placeholder, so `set_config` is the injection-safe form. The third argument `true` = `is_local` (equivalent to `SET LOCAL`).

## Service Pattern (sqlc, Tenant-Aware)

### `internal/user/service.go`
```go
package user

import (
    "context"
    "github.com/yourapp/internal/db"
    "github.com/yourapp/internal/store"
)

type Service struct {
    store *store.Store
}

// Tenant comes automatically from context via store.InTenant — the handler does NOT send tenant_id.
func (s *Service) ListUsers(ctx context.Context) ([]db.ListUsersRow, error) {
    var users []db.ListUsersRow
    err := s.store.InTenant(ctx, func(q *db.Queries) error {
        var err error
        users, err = q.ListUsers(ctx) // RLS + WHERE tenant_id active
        return err
    })
    return users, err
}

func (s *Service) CreateUser(ctx context.Context, in db.CreateUserParams) (db.CreateUserRow, error) {
    var out db.CreateUserRow
    err := s.store.InTenant(ctx, func(q *db.Queries) error {
        var err error
        out, err = q.CreateUser(ctx, in) // tenant_id filled by current_setting in SQL
        return err
    })
    return out, err
}
```

## Escape Hatch — Raw pgx for Dynamic Queries

Optional filters / search builders are awkward in sqlc (which needs static SQL). For these cases, write raw `pgx` **inside the same `InTenantRaw`** so RLS stays active:

```go
// in internal/store/store.go — raw variant: hand the raw pgx.Tx to fn.
// The "Raw" suffix = bypass sqlc, you write the SQL & Scan yourself. RLS stays active (same set_config tx).
func (s *Store) InTenantRaw(ctx context.Context, fn func(tx pgx.Tx) error) error {
    // same as InTenant, but hand the raw tx to fn
    // ... Begin → set_config → fn(tx) → Commit
}

// usage: list with optional filters
func (s *Service) SearchUsers(ctx context.Context, f UserFilter) ([]User, error) {
    sql := `SELECT id, name, email, role FROM tenant_users WHERE 1=1`
    args := []any{}
    if f.Role != "" {
        args = append(args, f.Role)
        sql += " AND role = $" + strconv.Itoa(len(args))
    }
    if f.Search != "" {
        args = append(args, "%"+f.Search+"%")
        sql += " AND name ILIKE $" + strconv.Itoa(len(args))
    }
    sql += " ORDER BY created_at DESC LIMIT 50"
    // RLS still filters tenant_id even though it isn't written in WHERE
    // ... run via s.InTenantRaw(ctx, func(tx) { rows, _ := tx.Query(ctx, sql, args...) ... })
}
```

## Redis — Cache & State Backend

Redis on the VPS is **not** the place for user sessions or login rate-limiting. That belongs to the edge (Cloudflare KV `CACHE_SSO`): the Worker validates the session and handles login throttling before forwarding. The backend doesn't read sessions from Redis at all — user identity comes from the **verified JWT** on each request (`AuthMiddleware`, see `auth-sso.md` / `rbac.md`), not from trusted headers. (The refresh-token rotation state is the one session-adjacent thing that does live in Redis — see below.)

| Need | Owner | Why |
|-----------|---------|--------|
| User session | CF KV `CACHE_SSO` | Validated at the edge on every request |
| Login rate-limit | CF KV `CACHE_SSO` | Blocked before reaching the backend |
| Cache DB query results | **Redis** | Only the backend knows the results |
| Distributed lock / idempotency | **Redis** | Atomic state across API instances |
| One-time codes (reset/verify) | **Redis** | Short TTL + single-use |
| Cross-instance cache invalidation | **Redis Pub/Sub** | Multiple API processes behind Nginx |

> **Tenant isolation in Redis = namespace discipline.** There's no RLS in Redis like in Postgres. A single Redis instance is used by all tenants, so **every tenant data key MUST be prefixed with `tenant:{tenantID}:`**. Keys without a tenant prefix are only for platform/cross-tenant data.

### `pkg/cache/redis.go`
```go
package cache

import (
    "context"
    "encoding/json"
    "errors"
    "fmt"
    "strings"
    "time"

    "github.com/redis/go-redis/v9"
    "github.com/yourapp/internal/tenant"
)

type Client struct {
    rdb *redis.Client
}

func New(rdb *redis.Client) *Client { return &Client{rdb: rdb} }

// tenantKey — ALWAYS used for tenant data. tenantID is taken from context,
// not a parameter, so it's impossible to mix up/cross tenants.
func tenantKey(ctx context.Context, parts ...string) string {
    t := tenant.MustFromContext(ctx)
    key := "tenant:" + t.ID
    for _, p := range parts {
        key += ":" + p
    }
    return key
}

var ErrCacheMiss = errors.New("cache miss")
```

### Cache-Aside (tenant-namespaced)
```go
func (c *Client) Get(ctx context.Context, category, id string) ([]byte, error) {
    val, err := c.rdb.Get(ctx, tenantKey(ctx, category, id)).Bytes()
    if errors.Is(err, redis.Nil) {
        return nil, ErrCacheMiss
    }
    return val, err
}

func (c *Client) Set(ctx context.Context, category, id string, val []byte, ttl time.Duration) error {
    return c.rdb.Set(ctx, tenantKey(ctx, category, id), val, ttl).Err()
}

func (c *Client) Del(ctx context.Context, category, id string) error {
    return c.rdb.Del(ctx, tenantKey(ctx, category, id)).Err()
}

// Cached — generic cache-aside helper: check the cache, on miss call the loader then store.
// Free function (Go methods cannot have type parameters).
func Cached[T any](ctx context.Context, c *Client, category, id string, ttl time.Duration,
    loader func(context.Context) (T, error)) (T, error) {

    var zero T
    if raw, err := c.Get(ctx, category, id); err == nil {
        var out T
        if json.Unmarshal(raw, &out) == nil {
            return out, nil
        }
    }
    fresh, err := loader(ctx)
    if err != nil {
        return zero, err
    }
    if raw, err := json.Marshal(fresh); err == nil {
        _ = c.Set(ctx, category, id, raw, ttl)
    }
    return fresh, nil
}
```

### Per-Tenant Invalidation (use SCAN, not KEYS)
```go
// KEYS blocks all of Redis in prod. Use SCAN incrementally.
func (c *Client) InvalidatePrefix(ctx context.Context, category string) error {
    pattern := tenantKey(ctx, category) + ":*"
    var cursor uint64
    for {
        keys, next, err := c.rdb.Scan(ctx, cursor, pattern, 100).Result()
        if err != nil {
            return err
        }
        if len(keys) > 0 {
            if err := c.rdb.Del(ctx, keys...).Err(); err != nil {
                return err
            }
        }
        cursor = next
        if cursor == 0 {
            break
        }
    }
    return nil
}
```

### Distributed Lock (single-instance Redis)
```go
// SET key val NX PX ttl → lock. Release uses Lua compare-and-del so it doesn't
// delete a lock owned by another process (if the TTL has already passed).
// Note: this lock is for a single Redis instance on the VPS, sufficient for coordination between
// API processes. For a Redis cluster/HA, consider Redlock.
func (c *Client) Lock(ctx context.Context, name, token string, ttl time.Duration) (bool, error) {
    return c.rdb.SetNX(ctx, tenantKey(ctx, "lock", name), token, ttl).Result()
}

var unlockScript = redis.NewScript(`
    if redis.call("GET", KEYS[1]) == ARGV[1] then
        return redis.call("DEL", KEYS[1])
    end
    return 0
`)

func (c *Client) Unlock(ctx context.Context, name, token string) error {
    return unlockScript.Run(ctx, c.rdb, []string{tenantKey(ctx, "lock", name)}, token).Err()
}
```

### Idempotency Key (dedup POST/webhook)
```go
// SetNX can reduce duplicate work for retry storms, but it is not a durable source of truth.
// For money, email, tenant provisioning, or any irreversible side effect, pair this with a
// PostgreSQL unique constraint / idempotency table that records pending/succeeded/failed states.
func (c *Client) ClaimIdempotency(ctx context.Context, key string, ttl time.Duration) (bool, error) {
    return c.rdb.SetNX(ctx, tenantKey(ctx, "idem", key), "1", ttl).Result()
}
```

Do not mark a side effect as "done" only in Redis before the database transaction succeeds. If Redis claims first and the DB write fails, a retry can be accidentally skipped. Durable idempotency belongs in PostgreSQL; Redis is only a fast duplicate suppressor.

### Refresh-Token Family — Rotation with Reuse Detection
```go
// The ONE piece of session-related state that lives in Redis (see auth-sso.md trust model).
// Edge access-sessions stay in CACHE_SSO (KV); but refresh ROTATION needs atomic
// compare-and-set to detect a stolen, already-rotated token — KV is eventually consistent
// and cannot do this safely. One key per login family: refresh_family:{familyID} → current_jti.
//
// NOTE: not tenantKey() — a refresh family is scoped to one user's login, and the refresh
// endpoint runs before a tenant tx is opened. tenant_id is carried in the signed token instead.
func refreshFamilyKey(familyID string) string { return "refresh_family:" + familyID }

// SeedFamily — at login: record the first jti for a new family.
func (c *Client) SeedFamily(ctx context.Context, familyID, jti string, ttl time.Duration) error {
    return c.rdb.Set(ctx, refreshFamilyKey(familyID), jti, ttl).Err()
}

// RotateFamily — atomic CAS: succeed (and store newJTI, resetting the sliding TTL) ONLY if
// the presented jti is the current one. A mismatch means the token was already rotated away
// (i.e. reused/stolen) → returns ok=false so the caller revokes the whole family.
var rotateFamilyScript = redis.NewScript(`
    if redis.call("GET", KEYS[1]) == ARGV[1] then
        redis.call("SET", KEYS[1], ARGV[2], "PX", ARGV[3])
        return 1
    end
    return 0
`)

func (c *Client) RotateFamily(ctx context.Context, familyID, expectedJTI, newJTI string, ttl time.Duration) (bool, error) {
    res, err := rotateFamilyScript.Run(ctx, c.rdb,
        []string{refreshFamilyKey(familyID)},
        expectedJTI, newJTI, ttl.Milliseconds(),
    ).Int()
    return res == 1, err
}

// RevokeFamily — kill the family (logout, or reuse detected). Every refresh in this family
// then fails RotateFamily, forcing re-login. To revoke ALL of a user's sessions, track their
// family IDs in a Set (refresh_user:{userID}) and delete each.
func (c *Client) RevokeFamily(ctx context.Context, familyID string) error {
    return c.rdb.Del(ctx, refreshFamilyKey(familyID)).Err()
}
```

### Pub/Sub — Cross-Instance Cache Invalidation
```go
// Multiple API processes behind Nginx. When one process writes & invalidates,
// broadcast so other processes also evict their local cache (if there's an in-memory layer).
const cacheEvictChannel = "cache:evict"

func (c *Client) PublishEvict(ctx context.Context, tenantID, category string) error {
    msg := fmt.Sprintf("%s:%s", tenantID, category)
    return c.rdb.Publish(ctx, cacheEvictChannel, msg).Err()
}

func (c *Client) SubscribeEvict(ctx context.Context, handle func(tenantID, category string)) {
    sub := c.rdb.Subscribe(ctx, cacheEvictChannel)
    go func() {
        for msg := range sub.Channel() {
            // payload = "{tenantID}:{category}"; tenantID UUID doesn't contain ':'
            parts := strings.SplitN(msg.Payload, ":", 2)
            if len(parts) != 2 {
                continue
            }
            handle(parts[0], parts[1])
        }
    }()
}
```

### Background Jobs (optional)
For async jobs (sending emails, generating reports, syncing to CF KV) use **asynq** (a queue on top of Redis). Include `tenant_id` in the job payload, and when the worker processes it, still wrap DB access via `store.InTenant` so RLS is active in the worker goroutine.

## Platform Routes (Superuser/Owner Admin)

Platform routes need **cross-tenant** queries (view all tenants, global aggregates). With FORCE RLS active, the `app_user` connection **cannot** do this — without an active tenant it sees 0 rows. So the platform uses a **second pool** with the `platform_user` role (`BYPASSRLS`).

```go
// PlatformStore uses the PLATFORM POOL (role platform_user, BYPASSRLS).

type PlatformStore struct {
    pool *pgxpool.Pool // platform_user — BYPASSRLS
}

func NewPlatform(pool *pgxpool.Pool) *PlatformStore { return &PlatformStore{pool: pool} }

// Cross-tenant: no set_config, RLS is bypassed by the role attribute.
func (h *PlatformHandler) ListAllTenants(w http.ResponseWriter, r *http.Request) {

```

> **Hard rules — never to be violated:**
> - `app_user` = `NOBYPASSRLS`. Tenant handlers ALWAYS go through `store.InTenant` (app pool).
> - `platform_user` = `BYPASSRLS`. Only for platform routes that are genuinely cross-tenant.
> - Don't merge the two pools. Don't give `app_user` the `BYPASSRLS` attribute "for convenience" — that kills the entire isolation guarantee.

## Error Handling & Validation

One error shape across the whole API. The frontend (`frontend-vue-cloudflare.md`) and every handler agree on it, so there is exactly one contract to code against.

### The error envelope
```json
{ "error": { "code": "validation_failed", "message": "Validation failed", "fields": { "email": "must be a valid email" } } }
```
- `code` — stable, machine-readable (frontend branches on this, not on `message`).
- `message` — human-readable, safe to display. NEVER contains internal detail (SQL, stack, file paths).
- `fields` — optional, only for validation errors: per-field message the UI maps onto inputs.

### `internal/httperr/httperr.go`
```go
package httperr

import (
    "encoding/json"
    "net/http"
)

// AppError — the only error type handlers return to the client.
type AppError struct {
    Status  int               `json:"-"`
    Code    string            `json:"code"`
    Message string            `json:"message"`
    Fields  map[string]string `json:"fields,omitempty"`
}

func (e *AppError) Error() string { return e.Code }

// Sentinel constructors — stable codes the frontend can branch on.
func Unauthorized() *AppError { return &AppError{http.StatusUnauthorized, "unauthorized", "Authentication required", nil} }
func Forbidden() *AppError    { return &AppError{http.StatusForbidden, "forbidden", "You don't have access to this", nil} }
func NotFound() *AppError     { return &AppError{http.StatusNotFound, "not_found", "Resource not found", nil} }
func BadRequest(msg string) *AppError { return &AppError{http.StatusBadRequest, "bad_request", msg, nil} }
func Validation(fields map[string]string) *AppError {
    return &AppError{http.StatusUnprocessableEntity, "validation_failed", "Validation failed", fields}
}

// Write — serialize the envelope. The ONLY way errors reach the client.
func Write(w http.ResponseWriter, e *AppError) {
    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(e.Status)
    json.NewEncoder(w).Encode(map[string]any{"error": e})
}
```

### Recover middleware — a panic must never leak internals

```go
// Recover — turn any panic into a generic 500. The client gets the request_id; the real
// detail is logged server-side. This is a security boundary: stack traces / SQL must NEVER
// reach the response body.
//
// The id shown to the client is the SAME request_id set by the RequestID middleware
// (observability.md) — already on every log line for this request. Do NOT mint a fresh id
// here, or the id in the 500 body would correlate with nothing.
func Recover(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        defer func() {
            if rec := recover(); rec != nil {
                reqID := obs.RequestIDFromContext(r.Context())
                // Context logger already carries request_id + tenant_id + user_id.
                logging.From(r.Context()).Error("panic recovered",
                    "panic", rec, "stack", string(debug.Stack()), "path", r.URL.Path)

                httperr.Write(w, &httperr.AppError{
                    Status: 500, Code: "internal_error",
                    Message: "Something went wrong. Reference: " + reqID,
                })
            }
        }()
        next.ServeHTTP(w, r)
    })
}
```

> **500 responses never leak.** A generic message + the request_id is all the client sees; full context (stack, SQL, `tenant_id`) lives only in server logs, keyed by that same id for triage. Treat any internal string in a 5xx body as a bug. Logger setup, the RequestID middleware, and the access log are in `observability.md`.

### Input validation at the handler boundary

Validate where untrusted input enters — the handler — using `go-playground/validator`. `tenant_id` still comes from context (never from the validated body; see Important Notes).

```go
import "github.com/go-playground/validator/v10"

var validate = validator.New()

type LoginInput struct {
    Email    string `json:"email"    validate:"required,email,max=255"`
    Password string `json:"password" validate:"required,min=8,max=200"`
}

// decodeAndValidate — bind JSON (checking the decode error, which is easy to forget)
// then run struct validation, returning a ready-to-write *AppError on failure.
func decodeAndValidate[T any](r *http.Request, dst *T) *httperr.AppError {
    if err := json.NewDecoder(r.Body).Decode(dst); err != nil {
        return httperr.BadRequest("malformed JSON body")
    }
    if err := validate.Struct(dst); err != nil {
        return httperr.Validation(fieldErrors(err)) // map validator tags → per-field messages
    }
    return nil
}

// fieldErrors — translate validator.ValidationErrors into the envelope's fields map.
func fieldErrors(err error) map[string]string {
    out := map[string]string{}
    var ve validator.ValidationErrors
    if errors.As(err, &ve) {
        for _, fe := range ve {
            out[strings.ToLower(fe.Field())] = messageFor(fe) // e.g. "email" → "must be a valid email"
        }
    }
    return out
}
```

> **Validation is mirrored, Go is authoritative.** The Vue side (`frontend-vue-cloudflare.md`) validates the same rules for instant feedback, but the backend check is the boundary — the client can be bypassed. Same principle as the RBAC wildcard logic (`rbac.md`): UI is convenience, server is truth.

### Resource not-found vs forbidden — prevent enumeration

> For **tenant-scoped resources**, return `404 not_found` for "doesn't exist" AND "exists but belongs to another tenant" — never `403`. A `403` would confirm the row exists, letting an attacker enumerate other tenants' IDs. RLS already makes other tenants' rows invisible (a cross-tenant `SELECT` returns zero rows → naturally 404), so this falls out for free if you don't special-case it. Note this is distinct from **route-level authz** (`rbac.md`): there a `403 forbidden` is correct because the user is authenticated and the route's existence isn't secret — they simply lack the permission.

## Important Notes

- **NEVER** use `tenant_id` from the request body/query — always from the JWT/context (`tenant.MustFromContext`)
- **RLS is the SECOND security layer, and must be `ENABLE` + `FORCE`** — `ENABLE` alone leaks for the table owner. See `database-schema.md`.
- **All tenant data access goes through `store.InTenant`** (app pool, `app_user`/`NOBYPASSRLS`) — `set_config(...)` and the sqlc query must share one `tx`, otherwise RLS leaks/empties
- **Platform routes use a SEPARATE pool** (`platform_user`/`BYPASSRLS`), not `store.InTenant`. That's the only cross-tenant path. Don't give `app_user` the `BYPASSRLS` attribute.
- **`internal/db/` is sqlc-generated — don't edit it manually.** Change the SQL in `query/*.sql` then run `sqlc generate`
- **Dynamic queries** (optional filter/search): use the raw `pgx` escape hatch via `store.InTenantRaw`, still inside an RLS-bound transaction
- **Two connection pools**: app pool (`app_user`) for all tenant handlers, platform pool (`platform_user`) for platform routes. Each is 1 pool for all tenants, not per-tenant.
- **One error shape**: every handler writes the `{ error: { code, message, fields? } }` envelope via `httperr.Write` — never plain-text `http.Error`, never raw internal detail. 500s carry a correlation ID only. Tenant-scoped resources return 404 (not 403) for cross-tenant misses. See Error Handling & Validation.
- **Don't swallow errors**: check the `json.Decode` error and don't `_`-discard service errors — a silently empty struct or ignored failure is how bad data reaches RLS-scoped queries.
- Golang context propagation: ensure all async functions/goroutines propagate context correctly
